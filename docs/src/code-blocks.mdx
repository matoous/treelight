title: Code Blocks
description: Render Markdown, MDX, and Astro code blocks with Treelight.

Treelight ships integrations for Markdown and Astro code blocks. Prefer `@treelight/plugin-rehype` when your docs framework accepts rehype plugins. Use `@treelight/plugin-rspress` for Rspress sites so Treelight owns the complete code-fence rendering path. Use `@treelight/plugin-remark` only when you need to transform Markdown `code` nodes before the rehype stage.

## This Docs Site

This site uses `@treelight/plugin-rspress` for every Markdown code block. Its
build-time highlighter loads a bounded set of common fence languages. Other
languages fall back to escaped, themed Treelight output, while the interactive
browser demo still loads the complete documented language catalog.

```ts title="docs/rspress.config.ts" {5-20}
import { defineConfig } from '@rspress/core';
import treelight from '@treelight/plugin-rspress';
import { markdownHighlighter } from './src/lib/markdown';

export default defineConfig({
  plugins: [
    treelight({
      copyButton: true,
      highlighter: markdownHighlighter,
      theme: 'github-dark',
      lineNumbers: true,
      languageMap: {
        js: 'javascript',
        md: 'markdown',
        sh: 'bash',
        ts: 'typescript',
      },
    }),
  ],
});
```

The custom theme imports `@treelight/plugin-rspress/copy` once. The plugin
bypasses Rspress's code-block renderer with a native `<pre>`, so frames, line
numbers, highlighted lines, and copy controls all come from Treelight. Rspress
still includes Shiki internally, but it does not render this site's code fences.

The block below is rendered by that same pipeline. It shows global line numbers, per-block `startLineNumber`, highlighted-line metadata, a per-block theme, and a title. Highlight ranges are source-line ranges, so `highlightLines="2-3"` highlights the second and third code lines even though the visible gutter starts at `41`.

```ts title="packages.ts" theme=dracula showLineNumbers startLineNumber=41 highlightLines="2-3"
type PackageName = `@treelight/${string}`;

const integrations: PackageName[] = [
  '@treelight/plugin-rehype',
  '@treelight/plugin-remark',
  '@treelight/plugin-astro',
  '@treelight/plugin-rspress',
];
```

## Rspress

Use the Rspress plugin when Treelight should render Markdown and MDX code blocks in an Rspress site:

```sh
npm i @treelight/plugin-rspress @treelight/javascript @treelight/theme-github-dark
```

```ts
import { defineConfig } from '@rspress/core';
import treelight from '@treelight/plugin-rspress';
import javascript from '@treelight/javascript';
import githubDark from '@treelight/theme-github-dark';

export default defineConfig({
  plugins: [
    treelight({
      languages: [javascript],
      themes: [githubDark],
      theme: 'github-dark',
      lineNumbers: true,
    }),
  ],
});
```

Import the stylesheet from your Rspress global CSS:

```css
@import "@treelight/plugin-rspress/styles.css";
```

## Rehype

Install the integration, the languages you want to highlight, and a theme:

```sh
npm i @treelight/plugin-rehype @treelight/javascript @treelight/theme-github-dark
```

Register the plugin in your Markdown pipeline:

```ts
import rehypeTreelight from '@treelight/plugin-rehype';
import javascript from '@treelight/javascript';
import githubDark from '@treelight/theme-github-dark';

export default {
  markdown: {
    rehypePlugins: [
      [
        rehypeTreelight,
        {
          languages: [javascript],
          themes: [githubDark],
          theme: 'github-dark',
        },
      ],
    ],
  },
};
```

Import the shared stylesheet from your app entrypoint or docs layout:

```ts
import '@treelight/plugin-rehype/styles.css';
```

## Astro

Use the Astro integration when Treelight should own Markdown code blocks across an Astro site:

```sh
npm i @treelight/plugin-astro @treelight/javascript @treelight/theme-github-dark
```

```ts
import treelight from '@treelight/plugin-astro';
import javascript from '@treelight/javascript';
import githubDark from '@treelight/theme-github-dark';
import { defineConfig } from 'astro/config';

export default defineConfig({
  integrations: [
    treelight({
      languages: [javascript],
      themes: [githubDark],
      theme: 'github-dark',
      lineNumbers: true,
    }),
  ],
});
```

The integration disables Astro's built-in Markdown syntax highlighter and installs Treelight into supported Satteri and unified Markdown processors. If you use a custom processor shape, add `@treelight/plugin-rehype` to that processor manually.

Import the stylesheet from an Astro layout:

```tsx
---
import '@treelight/plugin-astro/styles.css';
---
```

## Remark

`@treelight/plugin-remark` is compatibility-oriented. Use it when your pipeline only exposes remark plugins or when highlighted HTML must be produced before `remark-rehype`.

```ts
import remarkTreelight from '@treelight/plugin-remark';
import javascript from '@treelight/javascript';
import githubDark from '@treelight/theme-github-dark';

processor.use(remarkTreelight, {
  languages: [javascript],
  themes: [githubDark],
  theme: 'github-dark',
});
```

Because the remark plugin replaces Markdown code nodes with raw HTML, later HTML serialization must allow dangerous HTML.

## Copy Button

Set `copyButton: true` to add an accessible copy control to every Treelight code
block:

```ts
processor.use(rehypeTreelight, {
  copyButton: true,
  languages: [javascript],
});
```

Then import the matching browser runtime once in your client entrypoint:

```ts
import '@treelight/plugin-rehype/copy';
```

The stylesheet hides copy controls until the runtime is installed, so pages
without JavaScript continue to render ordinary static code blocks. The runtime
copies only source content; line-number gutters and other `aria-hidden` nodes
are excluded. After a successful copy, the button briefly shows a checkmark and
announces the configured copied label before returning to the copy icon.

Customize the accessible labels, tooltips, and reset delay with an options
object:

```ts
processor.use(rehypeTreelight, {
  copyButton: {
    label: 'Copy code',
    copiedLabel: 'Copied',
    errorLabel: 'Copy failed',
    resetAfter: 2000,
  },
});
```

Use `copy` or `copy=false` in fence metadata to override the global setting for
one block. The Rspress plugin bypasses Rspress's code-block component, so its
copy control is not rendered alongside Treelight's.

## Line Numbers

Set `lineNumbers: true` to enable line numbers for every block:

```ts
rehypeTreelight({
  languages: [javascript],
  lineNumbers: true,
});
```

Use `startLineNumber` when the first rendered line should not be `1`:

```ts
rehypeTreelight({
  lineNumbers: {
    startLineNumber: 41,
  },
});
```

Fence metadata can override the global setting:

````md
```ts showLineNumbers startLineNumber=41
export const answer = 42;
```

```ts showLineNumbers=false
export const quiet = true;
```

```ts lineNumbers=false
export const alsoQuiet = true;
```
````

The shorter `start` option and `lineNumbers` metadata are accepted as compatibility aliases, but new code should use `startLineNumber` and `showLineNumbers`.

This block is rendered live with line numbers disabled:

```ts showLineNumbers=false
export const quiet = true;
```

## Highlighted Lines

Use Expressive-Code-style ranges in code fence metadata:

````md
```ts {2,4-6}
const first = 1;
const second = 2;
const third = 3;
```
````

The explicit `highlightLines` metadata form is also supported:

````md
```ts highlightLines="1-2"
const first = 1;
const second = 2;
```
````

You can set default highlighted lines from plugin options:

```ts
rehypeTreelight({
  highlightLines: '2,4-6',
});
```

Use `highlightLines=false` in fence metadata to disable a global default for one block.

The following examples are rendered live by this docs site:

```ts {2,4-5}
const first = 1;
const second = 2;
const third = 3;
const fourth = 4;
const fifth = 5;
```

```ts highlightLines="1-2"
const first = 1;
const second = 2;
const third = 3;
```

## CSS Contract

The rendered code block stylesheet is exported by all Markdown integration packages:

```ts
import '@treelight/plugin-rehype/styles.css';
import '@treelight/plugin-remark/styles.css';
import '@treelight/plugin-astro/styles.css';
```

The stable classes are:

- `.treelight`
- `.treelight-code-block`
- `.treelight-copy-button`
- `.treelight-line`
- `.treelight-line-number`
- `.treelight-line-content`
- `.has-line-numbers`
- `.has-highlighted-lines`
- `.is-highlighted`

Customize the generated blocks with CSS variables:

```css
.treelight,
.treelight-code-block {
  --treelight-code-background: #111111;
  --treelight-code-border-color: #2f2f2f;
  --treelight-code-padding-inline: 1.25rem;
  --treelight-line-number-color: #9ca3af;
  --treelight-highlighted-line-background: rgba(255, 255, 255, 0.08);
  --treelight-copy-button-background: rgba(0, 0, 0, 0.82);
}
```

## Astro Code Component

Use the Astro component for dynamic snippets outside Markdown:

```tsx
---
import Code from '@treelight/plugin-astro/components/Code.astro';
import javascript from '@treelight/javascript';
import githubDark from '@treelight/theme-github-dark';
---

<Code
  code={`const greeting = 'hello';`}
  copyButton
  lang="javascript"
  languages={[javascript]}
  themes={[githubDark]}
  theme="github-dark"
  highlightLines="1"
  lineNumbers
/>
```

For pages with many dynamic snippets, create one highlighter and pass it through the `highlighter` prop.
